options {
    listen-on port 53 { 192.168.1.10; };

🛰️ Serveur DNS secondaire — Transfert de zone

Configuration d'un second serveur DNS sur 192.168.1.254 qui reçoit automatiquement les zones du primaire 192.168.1.10.

🟢 Primaire : 192.168.1.10 🟡 Secondaire : 192.168.1.254 🌍 Réseau : 192.168.1.0/24
🖥️

Rappel — Machines du même réseau

RôleNom DNSAdresse IPType
DNS primairefedora.ofppt.ma192.168.1.10master
DNS secondairens2.ofppt.ma192.168.1.254slave
16

🔁 1️⃣6️⃣ Configurer le transfert sur le primaire

/etc/named.conf (primaire)
options {
    listen-on port 53 { 192.168.1.10; };
    allow-query { 192.168.1.0/24; };
    allow-transfer { 192.168.1.254; };   # autorise secondaire
    also-notify { 192.168.1.254; };      # notifie secondaire
};

zone "ofppt.ma" IN {
    type master;
    file "/var/named/zone.dir";
    allow-transfer { 192.168.1.254; };
    also-notify { 192.168.1.254; };
};

zone "1.168.192.in-addr.arpa" IN {
    type master;
    file "/var/named/zone.inv";
    allow-transfer { 192.168.1.254; };
    also-notify { 192.168.1.254; };
};
  • allow-transfer — autorise le secondaire à copier la zone.
  • also-notify — prévient le secondaire immédiatement.
  • type master — source officielle de la zone.
17

📝 1️⃣7️⃣ Mettre à jour les fichiers de zone

/var/named/zone.dir
@       IN  NS  fedora.ofppt.ma.       # NS primaire
@       IN  NS  ns2.ofppt.ma.          # NS secondaire
ns2     IN  A   192.168.1.254         # IP secondaire
/var/named/zone.inv
@       IN  NS  ns2.ofppt.ma.          # NS secondaire
254     IN  PTR ns2.ofppt.ma.         # PTR secondaire
📌 Incrémenter le n° de série à chaque modification pour déclencher le transfert.
18

📦 1️⃣8️⃣ Installer BIND sur le secondaire

root@ns2: ~
[root@ns2 ~]# hostnamectl set-hostname ns2.ofppt.ma
[root@ns2 ~]# dnf install bind bind-utils -y

[root@ns2 ~]# firewall-cmd --permanent --add-service=dns
[root@ns2 ~]# firewall-cmd --reload

🛰️ 1️⃣9️⃣ Configurer named.conf sur le secondaire

/etc/named.conf (secondaire)
options {
    listen-on port 53 { 192.168.1.254; };
    allow-query { 192.168.1.0/24; };
    allow-transfer { none; };              # pas de transfert
};

zone "ofppt.ma" IN {
    type slave;                              # zone secondaire
    masters { 192.168.1.10; };               # serveur primaire
    file "slaves/zone.dir";                  # copie locale
};

zone "1.168.192.in-addr.arpa" IN {
    type slave;
    masters { 192.168.1.10; };
    file "slaves/zone.inv";
};
  • type slave — zone secondaire (copie du primaire).
  • masters — adresse du primaire à contacter.
  • file — fichier de copie locale.

03

3️⃣ Configurer le fichier principal du serveur DHCP

Éditer le fichier de configuration principal :

root@dhcp: ~
[root@dhcp ~]# vi /etc/dhcp/dhcpd.conf
/etc/dhcp/dhcpd.conf
# DHCP Server Configuration file.
# see /usr/share/doc/dhcp-server/dhcpd.conf.example
# see dhcpd.conf(5) man page

# pool LAN1
subnet 20.0.0.0 netmask 255.255.255.0 {
    range 20.0.0.2 20.0.0.100;              # 20.0.0.1 → dhcp-relay ens33
    option domain-name-servers 20.0.0.1 , 8.8.8.8;  # DNS primaire + secondaire
    option domain-name "ofppt1.ma";          # domaine LAN1
    option routers 20.0.0.1;                     # passerelle LAN1
    default-lease-time 86400;                    # 1 jour
    max-lease-time 259200;                        # 3 jours
}

# pool LAN2
subnet 30.0.0.0 netmask 255.255.255.0 {
    range 30.0.0.2 30.0.0.100;              # 30.0.0.1 → dhcp-relay ens37
    option domain-name-servers 30.0.0.1 , 8.8.8.8;
    option domain-name "ofppt2.ma";
    option routers 20.0.0.1;                     # ens33 ← server-dhcp
    default-lease-time 86400;
    max-lease-time 259200;
}

# Réservation d'adresse par MAC
host pc1 {
    hardware ethernet 08:00:07:26:c0:a5;          # MAC du client
    fixed-address 192.168.10.10;                # IP réservée
}
  • subnet — déclare un réseau avec masque.
  • range — plage d'adresses distribuables.
  • domain-name-servers — DNS fournis aux clients.
  • routers — passerelle par défaut du client.
  • default-lease-time — bail par défaut (secondes).
  • max-lease-time — bail maximal autorisé.
  • host … fixed-address — réservation MAC → IP fixe.
📌 Annotations du cours :
20.0.0.1 = IP du DNS primaire
8.8.8.8 = IP du DNS secondaire
04

[root@dhcp ~]# systemctl start dhcpd

🔗 DDNS — Mise à jour dynamique DNS

Le serveur DHCP met à jour automatiquement les zones DNS (directe et inverse) quand il attribue une adresse. Configuration côté DHCP (ddns-update-style interim) et côté DNS (allow-update).

🌍 Réseau : 192.168.2.0/24 🔵 DNS primaire : 192.168.2.200 🟣 DHCP server : 192.168.2.202 🟡 DNS secondaire : 192.168.2.254
01

1️⃣ Configurer le serveur DHCP pour le DDNS

Éditer /etc/dhcp/dhcpd.conf et activer la mise à jour dynamique :

root@ddns: ~
[root@ddns ~]# vi /etc/dhcp/dhcpd.conf
/etc/dhcp/dhcpd.conf
# pool 1
subnet 192.168.2.0 netmask 255.255.255.0 {
    range 192.168.2.100 192.168.2.199;        # .200 = DNS primaire
    range 192.168.2.203 192.168.2.253;        # .254 DNS sec + .202 DHCP
    option domain-name-servers 192.168.2.200,192.168.2.254;  # DNS prim + sec
    option domain-name "ofppt.local";              # nom de domaine
    option routers 192.168.2.1;                     # passerelle
    default-lease-time 600;                      # 10 min
    max-lease-time 7200;                          # 2 h

    ddns-update on;                               # active DDNS
    ddns-update-style interim;                   # style interim
    deny client-updates;                          # clients interdits
    ddns-domainname "ofppt.local";               # zone directe
    ddns-rev-domainname "2.168.192.in-addr.arpa";# zone inverse
    authoritative;                               # serveur officiel

    // zone directe
    zone ofppt.local. {
        primary 192.168.2.200;                    # IP DNS primaire
    }

    // zone inverse
    zone 2.168.192.in-addr.arpa. {
        primary 192.168.2.200;                    # IP DNS primaire
    }
}
  • ddns-update on — active les mises à jour DNS.
  • ddns-update-style interim — style de mise à jour (standard DHCP).
  • deny client-updates — clients interdits de mettre à jour eux-mêmes.
  • ddns-domainname — suffixe de zone directe.
  • ddns-rev-domainname — suffixe de zone inverse.
  • zone … { primary … } — adresse du DNS primaire à contacter.
02

2️⃣ Redémarrer le service DHCP

root@ddns: ~
[root@ddns ~]# systemctl restart dhcpd
[root@ddns ~]# systemctl status dhcpd
Active: active (running)
➡️ Après redémarrage, chaque bail DHCP déclenchera une mise à jour DNS auprès du primaire.
03

3️⃣ Autoriser les mises à jour sur le DNS primaire

Sur 192.168.2.200, éditer /etc/named.conf et autoriser le serveur DHCP à modifier les zones :

root@dns1: ~
[root@dns1 ~]# vi /etc/named.conf
/etc/named.conf (DNS primaire 192.168.2.200)
// zone directe
zone "ofppt.local" IN {
    type master;
    file "ofppt.local.db";
    allow-update { 192.168.2.202; };   # IP serveur DHCP
};

// zone inverse
zone "2.168.192.in-addr.arpa" IN {
    type master;
    file "2.168.192.db";
    allow-update { 192.168.2.202; };   # IP serveur DHCP
};
  • allow-update — autorise un serveur à modifier la zone.
  • 192.168.2.202 — IP du serveur DHCP autorisé.
⚠️ Sans cette directive, le serveur DHCP ne pourra pas écrire dans la zone → erreur « update failed: REFUSED ».
04

4️⃣ Désactiver le firewall

root@dns1: ~
[root@dns1 ~]# systemctl stop firewalld
➡️ Stoppe le pare-feu pour éviter qu'il bloque les mises à jour DNS dynamiques entre le serveur DHCP et le DNS.
05

5️⃣ Désactiver SELinux

root@dns1: ~
[root@dns1 ~]# setenforce 0
(SELinux est maintenant en mode permissif)

# Vérification
[root@dns1 ~]# getenforce
Permissive
⚠️ setenforce 0 = mode Permissive (aucun blocage) · setenforce 1 = mode Enforcing (contrôle de sécurité actif).
